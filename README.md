# epicormic-paper

Experiments, analysis, and manuscript for the epicormic paper: pre-registered
calibration, power, sequential-detection, longitudinal hosted-canary, and
cost-and-energy studies of [epicormic](https://github.com/jemsbhai/epicormic)
0.2.0, the provider drift detector and containment layer for
[pollard](https://github.com/jemsbhai/pollard)-governed AI systems. The
package source stays in its own repository; this repository holds what is
needed to plan, run, verify, and report the experiments and to build the
paper.

Working title: "epicormic: detection and containment of provider drift in
governed AI systems". Target venue: decided after EXP-A to EXP-C report;
drafted to the standard of the top tier throughout.

## Repository rules

1. Every experiment is pre-registered. Its hypotheses, design grid, seeds,
   scorer set, pinned package versions, and analysis plan are written to
   `experiments/<exp>/PREREGISTRATION.md` and `protocol.json`, the protocol
   digest is recorded in `LOGBOOK.md`, and the commit is tagged before any
   data are collected. A protocol changes only by a new, dated version that
   keeps the old one in place.
2. `LOGBOOK.md` is append-only. The plan entry is written before a run and
   the result entry after it. Failed runs and negative results are entries
   too; corrections are dated addenda that cite the original entry.
3. Every number in `findings.md` and in the paper traces to a run id in
   `experiments/run_registry.yaml`, and every paper number is read from
   `analysis/generated/`. Nothing is copied from a terminal or a notebook.
4. Raw observation stores are never committed; run manifests, environment
   snapshots, seeds, frozen protocol copies, and summaries are. An archived
   raw store is referenced by its SHA-256 digest in the registry.
5. The local control of epicormic decision D11 is present in every
   experiment. A drift verdict on the control is a defect in epicormic, not a
   finding.
6. Hosted spend for EXP-D stays under the 10 USD per month cap of decision
   D17, enforced by a pollard budget on every window run.
7. No em-dashes, en-dashes, curly quotes, or the words in
   `tools/banned_words.txt` anywhere in Markdown, Python, notebooks, or TeX.
   `tools/scan_vocabulary.py` enforces this and CI runs it.
8. Every bibliography entry is verified against a primary publication page
   or official documentation, with a record in
   `paper/references/verified_sources.json`.
9. Scripts and notebooks are front-ends over `src/epicormic_lab`. Experiment
   logic lives in the package only, so a script run and a notebook run of one
   protocol are the same computation and register the same way.

`src/epicormic_lab/pins.py`; the test suite checks the installed versions
against the pins, and every run manifest records them.

## Layout

```
LOGBOOK.md                  append-only experiment logbook (plan before, results after)
findings.md                 curated summary plus append-only raw findings, every number carries a run id
src/epicormic_lab/          the experiment code (panels, providers, protocol loading, runs, analysis)
scripts/                    run_exp_*.py, snapshot_environment.py, freeze_protocol.py, make_figures.py
notebooks/                  thin front-ends over the package; exploratory work never feeds the paper
experiments/                one directory per experiment: PREREGISTRATION.md, protocol.json, runs/
experiments/run_registry.yaml   every run: id, protocol digest, commit, environment, status, outcome
data/                       pinned canary panels with digests, checksums, provenance
analysis/generated/         committed value-free JSON summaries; the only source of paper numbers
figures/                    publication figures, generated by scripts/make_figures.py only
paper/                      manuscript sources, bibliography, and source verification records
tools/                      vocabulary and typography scan
tests/                      tests of the experiment code, 100 percent line coverage
```

## Setup

Windows PowerShell with the system Python (3.12 here; 3.10 or newer works):

```powershell
git clone https://github.com/jemsbhai/epicormic-paper.git
Set-Location epicormic-paper
python -m pip install -e ".[dev]"
```

Linux and macOS use the same commands with `cd`. The install pulls the
pinned releases of epicormic and pollard from PyPI. Extras: `control` for
the local control, `hosted` for EXP-D, `energy` for EXP-E, `figures` and
`notebooks` for the analysis front-ends.

## Checks before every push

```powershell
python -m pytest --cov=epicormic_lab --cov-report=term-missing
python -m ruff check src tests scripts tools
python -m mypy src
python tools/scan_vocabulary.py
```

CI runs the same four checks on Ubuntu and Windows with Python 3.10 and 3.12
and fails below 100 percent line coverage of `epicormic_lab`.

## Experiments

Defined in section 16 of `docs/PLAN.md` in the epicormic repository. Each
opens with a pre-registration in its own directory. `HANDOFF.md` says who
runs which arm.

| Id | Question | Providers | Status |
| --- | --- | --- | --- |
| EXP-A | Calibration: is the false-alarm rate of the pooled test within the binomial interval of alpha, and does the e-process alarm on at most alpha of A/A streams? | mock, local control | mock arm pre-registered (`experiments/exp_a_calibration/`, version 2026-10-28-r2 at tag `exp-a-prereg-r2`, against epicormic 0.2.0) and runnable with `scripts/run_exp_a.py`; control arm protocol follows the throughput report |
| EXP-B | Power: which (N, panel size) reaches 0.8 power per drift type and effect size? | mock, local control | not yet pre-registered |
| EXP-C | Sequential detection delay against false-alarm rate for the pooled test, CUSUM, Page-Hinkley, the e-process and the state machine after a change at a known window; calibration of the defaults | mock, local control | mock arm revised before freeze (`experiments/exp_c_sequential/`, version 2026-10-30-r2; tag `exp-c-prereg` after review and checks); runner follows |
| EXP-D | Hosted canary: 28 daily windows on cheap-tier models from four provider families with a declared snapshot switch on day 15, beside the control and a local silent-change arm (GGUF swap under an unchanged name), under the 10 USD per month cap | hosted, local control | not yet pre-registered |
| EXP-E | Cost and energy of monitoring: tokens, USD, wall-clock, and NVML joules per window against the power reached in EXP-B | mock, local control | not yet pre-registered |

Execution order (decisions D24 to D26 in the epicormic plan): EXP-A, then
EXP-C, whose delay results set the detection-delay bound EXP-D
pre-registers, then EXP-D opens and collects daily while EXP-B and EXP-E
run.

## Run lifecycle

1. Write `experiments/<exp>/PREREGISTRATION.md` and `protocol.json`; record
   the protocol digest from `scripts/freeze_protocol.py` in the logbook plan
   entry; commit `docs(logbook): EXP-X planned`; tag `exp-x-prereg`.
2. Write the runner and analysis code with tests; run the `smoke` profile as
   an instrumentation check that produces no evidence; tag `exp-x-frozen`.
3. Run the `full` profile from a clean tree with the registered digest
   (`python scripts/run_exp_a.py --profile full --run-id exp-a-full-001
   --digest <hex> --workers N`): the script copies the frozen protocol into
   the run directory, writes `environment.json` and `seed.json`, writes one
   summary per cell as it completes, and appends the run to the registry.
4. Append the result entry to the logbook, add the raw finding, regenerate
   `analysis/generated/` and the figures; commit; tag `exp-x-final`.
